SANKET An engine that reads an unsafe-act, unsafe-condition or near-miss report and answers one question: could this have killed someone? This sheet is how it is built, end to end.

A

The path a report takes

Seven steps, in order, from a worker on site to a re-ordered queue on a safety officer's screen. Nothing here runs on a schedule; every step is triggered by the one before it.

  1. 01Worker writes or speaks the report React screen. Typing is the normal path. Speech exists because a worker at a wellhead has gloves on.
  2. 02Speech becomes text POST /transcribe sends the audio to Whisper (whisper-large-v3). Skipped entirely when the report was typed.
  3. 03The API validates the payload POST /reports/worker. Pydantic rejects a malformed body before any model sees it.
  4. 04One call crosses the classifier boundary classify(report_text). Everything above this line is unaware of which model answered. Section B is what happens below it.
  5. 05The verdict is appended, never updated A new row in predictions, stamped with the model version that produced it. Re-classifying a report adds a row; it does not overwrite the old one.
  6. 06The newest verdict per report is selected The latest_predictions view. A sibling view scopes to a single model version, so a prompt change cannot half-populate a dashboard.
  7. 07The queue re-orders and a person decides Admin triage lists by date, then by severity within a date. The officer dispatches or archives. SANKET never closes a report.
B

The classifier boundary, and what happens when the model fails

This is the part worth arguing about. A hosted language model is a network call that can hang, rate-limit, or return something that is not the shape you asked for. All three are handled, and the system says out loud when it has degraded.

Normal path

1   Cache lookup

Keyed on the report text. A repeated report never pays for a second API call.

miss ↓

2   Primary classifier

Reads the narrative against the written rubric and returns the three gates plus its reasoning.

3   Cached, then returned

schema rejected → retry once
rejected again, raised, or timed out ↓

4   Baseline classifier

A local model, trained on the gold labels. No network, no API key, answers in milliseconds.

TF-IDF + logistic regression
↓

5   Returned, and flagged

The interface says degraded mode — keyword baseline in plain words. It does not quietly serve a worse answer.

is_fallback = true · not cached
A degraded answer is never written to the cache. The cache has no expiry, so storing a fallback would pin it to that report permanently: every later call returns it instantly, with no error and no log line. One bad minute from the model would become a silent downgrade with no way back. Recomputing next time is the system recovering, which is the entire point of having a degraded mode.
C

The label is computed, not typed

A precursor flag is the conjunction of three gates. That rule lives in the database as a constraint, so no prompt revision, no migration and no careless insert can redefine what the word means.

-- predictions table
CONSTRAINT precursor_requires_all_three_gates CHECK (
    is_sif_precursor = (
        hazard_assessment = 'yes'
        AND control_status IN ('absent', 'failed')
        AND severity >= 4
    )
)

A second constraint enforces the rubric's other rule: a control status may only be recorded when a hazard was actually identified. Silence is not evidence of absence — a report that names no barrier is unclear, not absent.

D

What is stored

Five tables and two views. The split between machine verdicts and human labels is deliberate: they are never mixed, which is what makes measuring the model against people possible at all.

RelationHoldsWhy it is shaped this way
sites The site taxonomy Referenced by reports, so a typo cannot invent a new site.
reports The narratives themselves Each row is tagged synthetic, osha or worker, so no result can blur written-for-the-prototype data with real narratives.
predictions One row per classification Append-only and version-stamped. The history of what the model used to think survives every prompt change.
gold_labels Human judgements One row per annotator per report, plus a tiebreak row that records which gate the two disagreed on.
report_status Triage state active, dispatched or archived. Kept apart from the verdict, because a human decision is not a model output.
latest_predictions View The newest verdict per report, which is what every dashboard reads.
latest_predictions_by_version View The same, scoped to one model version, so a partly re-classified corpus cannot empty a dashboard.
E

The stack

Nothing exotic, and nothing that needs a GPU. Every piece was chosen so that a team of six could finish it and a judge could read it.

ClientReact (Vite) Two screens: a worker analyzer and an admin triage board.

G

Two decisions that shape everything else

Rank by rate, not by count

A site that reports honestly logs more incidents. Counting them punishes it, and the busiest site always looks worst. The dashboard ranks by precursors divided by reports, with small groups held back from the top.

The system ranks; a person decides

There is no route that closes a report on the model's say-so. The only thing SANKET changes is the order a safety officer reads them in.

Both are load-bearing. The first is why the risk board is usable at a company where reporting culture varies by site. The second is why a wrong verdict costs a few minutes of attention rather than a missed hazard.
